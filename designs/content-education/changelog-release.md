# Changelog & Release Notes

## Intent
Page de notes de version : suivre l'évolution d'un produit dans le temps.

Catégorie : Contenu & Éducation. Ton : chronologique, factuel, technique, clair.

## Style
- Frise verticale avec date à gauche et contenu à droite
- Badges colorés par type (nouveauté, correction, rupture)
- Numéros de version en mono
- Captures d'écran optionnelles par entrée

## Colors
- Mode: light
- Primary: #7C3AED
- Secondary: #F5F3FF
- Background: #FFFFFF
- Surface: #FAFAFA
- Text: #18181B
- Text Muted: #71717A
- Border: #E4E4E7
- Background treatment: plain

## Typography
- Heading font: Inter
- Body font: Inter
- Hero: 36px, weight 700, tracking -0.02em
- H2: 22px, weight 600, tracking -0.01em
- Body: 16px, line-height 1.7
- Case: none
- Détail: Version en mono dans une pastille violette, date en gris à gauche

## Layout
- Container: 860px
- Hero: editorial
- Section principale: steps
- Espacement entre sections: 56px entre entrées
- Grille: colonne de dates 120px + contenu

## Spacing & Shape
- Border radius: 8px
- Borders: 1px solid #E4E4E7
- Shadows: aucune

## Animation
- Load: aucune
- Hover: la ligne de la frise s'épaissit
- Scroll: chargement des entrées plus anciennes

## Components
- En-tête avec abonnement RSS
- Filtres par type de changement
- Frise des versions
- Entrée détaillée avec capture
- Lien vers la documentation
- Pied de page

## Sections Order
1. En-tête avec abonnement RSS
2. Filtres par type de changement
3. Frise des versions
4. Entrée détaillée avec capture
5. Lien vers la documentation
6. Pied de page

## Do / Don't for AI
**Do:**
- Dater et numéroter chaque entrée
- Signaler explicitement les ruptures de compatibilité
- Proposer un flux RSS

**Don't:**
- Pas d'entrée sans version ni date
- Pas de description vague du type « améliorations diverses »
- Ne pas mélanger les types de changement dans un même bloc

## Responsive
Mobile : date au-dessus du contenu, frise sur le côté gauche conservée.
